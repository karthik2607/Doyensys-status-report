Workstream 01

FacilityVUE 2.0 — Local Dev Environment Setup & Validation

While setting up and validating the local development environment, we identified and resolved three issues. Each was committed to its own dedicated branch, with a pull request raised against dev for review.

01

Windows Dev Environment — air Live-Reload Failure

fix/air-windows

Developers on Windows couldn't start the Go backend services via air, the standard live-reload tool — the build succeeded, but the binary lacked the .exe extension Windows needs to execute it. Added a Windows-specific build override to both backend configs. Additive change; no effect on macOS/Linux workflows or deployed environments, since production runs through an independent Docker/CI pipeline that doesn't use air. Verified working on a clean Windows setup for both services.

02

Client App — PDF Preview Resource Leak

fix/pdf-preview-leak

The in-app PDF preview (Import Assessment review workspace) had an incorrect type definition masking two real defects: PDF documents and their background rendering resources were never released when a preview closed, and the rendering call used an outdated API parameter no longer aligned with the current PDF library version. Both corrected. Isolated to a single component with no other codebase dependencies; type-checking now passes with zero errors, and an architectural review confirmed no impact to any other feature.

03

Repository Housekeeping — Python Env Exclusion

chore/gitignore-client-worker-venv

Added a repository ignore rule for local Python virtual environments created by the data-processing worker service, preventing accidental commits of large, environment-specific files to source control. No functional impact.
